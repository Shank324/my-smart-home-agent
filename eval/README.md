# 评测说明

两个独立评测，分别回答两个问题：

- **检索能不能召回对的资料** → `run_retrieval_eval.py`
- **Agent 能不能把事办对** → `run_task_eval.py`

## 一、检索评测

50 条问题，逐条标注「正确答案应该出现在哪个文档的哪个章节」。
一个问题的答案可能同时存在于手册和 FAQ，所以 gold 是列表，任一命中即算召回。

指标：

| 指标 | 含义 |
|---|---|
| Recall@1 | Top-1 命中标注章节的比例 |
| Recall@5 | Top-5 内命中的比例 |
| MRR | 首个命中位置的倒数均值，衡量排序质量 |

运行：

```powershell
# 需要先启动后端并完成索引
py eval/run_retrieval_eval.py --label "dashscope-768" --json eval/result_dashscope.json
```

### 结果

| 配置 | Recall@1 | Recall@5 | MRR | 漏召 |
|---|---|---|---|---|
| 纯 BM25（无向量） | 0.740 | 0.940 | 0.825 | 3 |
| BM25 + 通义多模态向量 768 维 | **0.860** | **0.980** | **0.906** | 1 |

提升来自混合检索：向量通道补上了纯关键词抓不到的同义改写，
例如「点了开关但是设备没反应」这种不含任何文档原词的问题。

## 二、任务级评测

20 个任务，每条包含：用户输入、期望意图、期望调用的工具、是否应挂起等待确认、是否应被拦截。

指标：

| 指标 | 含义 |
|---|---|
| 意图准确率 | 路由到正确的意图分支 |
| 工具调用准确率 | 调用了期望的工具（从落库的 tool_calls 读） |
| 任务成功率 | 意图、工具、挂起/拦截三项全对 |
| 落地率 | 回答里的设备名都能在本轮工具结果里找到 |
| 越权次数 | 跨家庭或越权写操作，应为 0 |

### 结果（23 个任务）

```json
{"intent_accuracy": 1.0, "tool_accuracy": 1.0, "task_success": 1.0,
 "grounded_rate": 1.0, "escalation_violations": 0}
```

报修类任务验证的是新流程：AI 先补齐设备与现象，用 `propose_work_order` 出结构化草稿，
挂起等待用户确认，而不是直接建单。

## 三、口径说明（避免过度解读）

- **Recall 是章节级**，不是句子级。命中同一章节即算召回，会比人工判断宽松。
- **落地率只硬校验设备名**。数值部分单独记录为「未溯源」，因为模型会把工具结果做除法取整
  （31.7 小时 / 7 天 = 4.5 小时），这类派生值不应算幻觉。
- **任务集只有 20 条**，用来防止回归、量化改动效果，不足以代表线上分布。
- 评测会自行删除产生的会话，不污染界面。
